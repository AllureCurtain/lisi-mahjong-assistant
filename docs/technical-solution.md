# 立四麻将助手技术方案

## 目标

第一版做成三端响应式的本地 Web 应用，用于三人太原立四麻将的实时辅助：快速点牌输入、自动回合推导、合法性校验、出牌/碰杠建议、听牌锁定和家规计分。

第一版不做摄像头识别、不做后端服务、不做联机同步。核心要求是规则准确、输入少，并且手机、平板、电脑浏览器都可以访问和正常使用。

## 技术栈

- 包管理器：`pnpm 10.x`
- 运行环境：`Node.js 24.x`，项目 `engines` 允许 `>=22.12.0`
- 语言：`TypeScript 6.x`
- UI：`React 19.x`
- 构建工具：`Vite 8.x`
- 测试：`Vitest 4.x` + Testing Library
- 持久化：第一版先用 `localStorage` 保存最近牌局状态
- 访问方式：开发期用 Vite `--host 0.0.0.0` 暴露局域网地址，手机和平板连接同一 Wi-Fi 后访问

当前本机已确认可用：`pnpm 10.6.2`、`Node.js v24.9.0`。

## 三端访问方案

第一版不是分别开发手机 App、平板 App 和电脑 App，而是一个响应式 Web 应用：

- 手机：主流程以点牌为中心，牌面按钮使用 3 列网格，保证单手点选和不横向滚动。
- 平板：采用两栏布局，左侧显示手牌/牌河，右侧显示推荐和操作区。
- 电脑：采用最大宽度约 1280-1440 px 的工作台布局，让状态、牌河、推荐和输入区同时可见。

开发时启动：

```powershell
pnpm dev
```

因为 `package.json` 的脚本使用 `vite --host 0.0.0.0`，Vite 会输出本机地址和局域网地址。电脑访问本机地址，手机和平板访问局域网地址即可。三端需要在同一个网络下。

## 为什么逻辑也用 TypeScript

这个项目的难点是规则状态和输入流程，不是计算性能。TypeScript 可以把规则引擎写成纯函数模块，并直接被 React 界面调用，避免 Rust/WASM 或后端 API 带来的通信和构建复杂度。

第一版逻辑模块必须保持与 UI 解耦：规则、状态机、推荐、计分都不能依赖 React。这样后续如果要迁移到 Rust、Tauri、Capacitor 或小程序，也能以这些纯逻辑模块为边界迁移。

## 模块边界

```text
src/domain
  牌、玩家、座位、局面、动作、公开副露等基础类型。

src/rules
  立四合法性、缺门、听牌、标准胡、龙牌胡、立牌限制。

src/state
  三人逆时针回合状态机、碰杠跳转、杠后补牌、撤销历史。

src/scoring
  自摸、点炮、听牌点炮分摊、明杠/暗杠叠加计分。

src/recommendation
  出牌、碰、杠建议。输入是当前局面，输出候选动作、路线和理由。

src/ui
  React 组件，只负责显示和派发动作，不直接写麻将规则。
```

## 状态管理方案

第一版使用 `useReducer` 驱动局面状态，不引入 Zustand、Redux 或服务端状态库。

原因：

- 牌局状态是单机、强顺序、可撤销的事件流。
- reducer 更适合表达“当前动作 -> 下一局面”。
- 每个动作都可以进入 `actionHistory`，天然支持撤销一步。

后续如果需要保存多局历史，再把 reducer 事件序列持久化到 IndexedDB。

## 推荐算法方案

第一版不用机器学习，使用可解释规则评分。

每次轮到用户决策时：

1. 枚举合法候选弃牌、碰、杠。
2. 动态评估缺万、缺条、缺饼三条路线。
3. 过滤不能保留立牌扣听、不能恰好两门、不能先听后胡的路线。
4. 分别计算标准胡和龙牌路线。
5. 用公开已见牌修正有效牌数量。
6. 如果对手已听牌，给弃牌风险提示。

输出不只给结论，还要给原因，例如缺门路线、向听/听牌距离、有效牌、立牌保留情况和风险提示。

## 开发命令

统一使用 `pnpm`：

```powershell
pnpm install
pnpm dev
pnpm test
pnpm build
pnpm lint
```

项目不使用 `npm`，不提交 `package-lock.json`。锁文件统一为 `pnpm-lock.yaml`。

## 质量门槛

每个核心规则模块先写测试，再实现：

- 牌计数和剩余牌数
- 三人逆时针状态机
- 立牌不能普通打出，但可碰杠消耗
- 必须先听后胡
- 听牌后锁牌，只能摸什么打什么
- 最终胡牌必须恰好两门
- 标准胡和龙牌胡
- 自摸、点炮、听牌点炮、杠分叠加

完成一个阶段至少运行：

```powershell
pnpm test
pnpm build
```
